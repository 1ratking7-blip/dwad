# Сессия 2026-07-28 (001) — Telegram-пост + аудит плавающих виджетов

## Часть 1 — пропущенный пост в Telegram
Пользователь напомнил про забытый пост. Проверил `Scripts/posts/schedule.json` +
GitHub Actions API (`telegram-daily-post.yml`) — за 36+ часов workflow отработал всего
1 раз (26 июля), на 27 июля прогон вообще не создался (известное ограничение GitHub:
schedule-триггеры могут пропускаться под нагрузкой платформы, не баг скрипта).
Опубликовал вручную ("Футбол — 16 лет", message_id 298) через
`Scripts/post_scheduled.py 2026-07-27` (тот же код, что использует автоматика — не
переизобретал), сразу закоммитил+запушил `schedule.json`, чтобы автоматика не
продублировала при следующем срабатывании. Поставил разовую сессионную проверку на
19:14 ICT того же дня (`CronCreate`, one-shot) — сработает только если сессия
останется открытой.

## Часть 2 — Metricool MCP (консультация, без изменений в коде)
Пользователь спросил про Metricool MCP. Проверил через WebSearch (не был на памяти,
актуальных данных не было): официальный MCP есть, бесплатный сам по себе, платный
тариф Metricool для API. Поддерживает Instagram/FB/X/TikTok/LinkedIn/YouTube/
Pinterest/Threads/Bluesky/**Twitch** — НЕ поддерживает Telegram. Вывод: закрыл бы дыру
по каналам, где сейчас вообще нет автопостинга (Instagram/FB/X/TikTok — контент есть,
публикации нет), но не решает именно ту проблему с Telegram, что чинили в Части 1.
Риск: write-доступ к живым OAuth-аккаунтам — на порядок больше blast radius, чем
нынешний scoped Telegram bot-токен. Пользователь решил отложить ("забыли про
метрокул") — ничего не подключено.

## Часть 3 — аудит сайта, реальные баги найдены и исправлены
Пользователь попросил аудит + фикс + пуш. Нашёл 3 реальных коллизии плавающих
UI-виджетов (не гипотетических — воспроизведены и исправлены с проверкой скриншотами):

1. **`AchievementToast` vs `BackToTop`** — оба `bottom-6 right-6` на десктопе.
   Любое достижение, сработавшее после скролла >600px (порог показа BackToTop),
   рисовалось прямо поверх кнопки. Исправлено: `bottom-40 lg:bottom-24 right-6`.
2. **`GoldModePill` vs `SocialProof`** — оба `bottom-6 left-6`. Золотой режим,
   активированный пока показывался тост с примером выигрыша, накладывался на него.
   Первая попытка (`md:bottom-36`) оказалась недостаточной — перепроверил скриншотом
   на 900px, всё ещё задевало карточку. Итог: `bottom-24 md:bottom-56 lg:bottom-36`.
3. **`SocialProof` vs `MobileStickyCta`** (не мой баг — существовал раньше моих
   правок) — `SocialProof` показывается с `md` (768px), `MobileStickyCta` скрывается
   только на `lg` (1024px) — в диапазоне 768-1023px оба видны одновременно, и
   sticky-бар почти полностью прятал тост за собой. Исправлено тем же паттерном,
   что уже использует `BackToTop`: `bottom-24 lg:bottom-6`.
