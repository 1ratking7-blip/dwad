# Сессия 2026-07-27 (001) — сгенерированы фото для luxury-редизайна, 4 из 6 вживлены в код

## Контекст
`design/prompts/` (сессия по luxury-редизайну, дата в README — тоже 2026-07-27, написана до
этой сессии) содержала 6 готовых промтов под фото для замены CSS/SVG-плейсхолдеров
(`LuxuryCar.tsx`, `MetalCard.tsx`, `NightSkyline.tsx`, `FloatingWealth.tsx`) — на тот момент
без инструмента генерации картинок. В этой сессии инструмент (`mcp__gpt__generate_image`,
gpt-image-2) стал доступен, пользователь попросил продолжить работу над дизайном.

## Сгенерировано
Все 6 промтов из `design/prompts/01..06` прогнаны через `gpt-image-2`:
- `hero-car.webp`, `night-city.webp`, `metal-card.webp`, `money-coins.webp`,
  `lifestyle-chips.webp`, `section-cards-sprite.webp` — все в `Landing/public/images/`.
- Прозрачный фон (`transparentBackground: true`) **не поддерживается** этой моделью (400
  ошибка) — карту и деньги перегенерировал с непрозрачным `#0A0D12` фоном (это и так был
  предусмотренный в промтах fallback).
- Модель отдаёт только PNG; сырые файлы весили ~1.7–2.2 МБ каждый — неприемлемо для perf
  (сайт уже проходил серьёзный Lighthouse-аудит, см. сессию `2026-07-21_001.md`). Конвертнул
  все 6 в WebP через `npx sharp-cli` (quality 85, без установки зависимости в проект) —
  результат ~100–190 КБ каждый (сжатие ~15-20x), оригинальные PNG удалены из репозитория.

## Вживлено в код (4 из 6 — компоненты с чёткой привязкой к промту)
- `LuxuryCar.tsx` — SVG-силуэт машины → `<img src="/images/hero-car.webp">`, тilt/float-обёртка сохранена.
- `NightSkyline.tsx` — SVG-небоскрёбы с анимацией окон → `<img src="/images/night-city.webp">`,
  parallax-обёртка и ground-haze градиент сохранены, мёртвый код (`BUILDINGS`, `windowRects`) удалён.
- `MetalCard.tsx` — CSS-карта (чип/маркер/линии) → `<img src="/images/metal-card.webp">`.
  Сгенerированное фото — портретная диагональная композиция (2:3), а не landscape-пропорция
  банковской карты как в исходном CSS-макете — контейнер пересчитан на `aspect-[2/3]`
  вместо `aspect-[1.586/1]`, `tilt-card`/`card-shine-loop` поверх фото сохранены.
- `FloatingWealth.tsx` — 6 SVG-частиц (купюры/монеты) с раздельным дрейфом/спином →
  **упрощено до одной** `<img src="/images/money-coins.webp">` с `bill-drift-a`: у модели нет
  прозрачного фона, отдельных cutout-элементов физически нет (это один студийный кадр, не
  спрайт из вырезанных предметов), поэтому многочастичная система была бы фикцией поверх
  одной картинки. Тёмный фон фото (#0A0D12) достаточно близок к фону страницы, читается как
  мягкий cutout без реального альфа-канала.

## Не вживлено (2 из 6 — нет готового слота в текущей структуре)
- `lifestyle-chips.webp` (казино-фишки, для "секции бонусов/соцдоказательства") — такой
  секции в коде нет (`SocialProof.tsx` — маленький floating-тост, не место для крупного фото).
- `section-cards-sprite.webp` (3×2 сетка из 6 мини-сцен для карточек разделов) — в `Games.tsx`
  4 карточки с lucide-иконками, тематически не совпадающими с 6 сгенерированными сюжетами
  1-в-1; чтобы использовать, тайлы пришлось бы нарезать на отдельные файлы и подобрать
  соответствие — решил не гадать самостоятельно, это отдельное дизайн-решение.

Оба файла лежат готовые в `Landing/public/images/`, ждут решения пользователя о размещении.

## Проверено
- `npm run build` (`tsc && vite build`) — чисто, без ошибок.
- Реальный скриншот через Playwright (Chromium, `npx playwright@1.55`, браузер докачан) на
  `localhost:3000` — десктоп 1440×1000 и мобильный 390×844. Десктоп: машина/карта/город/деньги
  собраны в цельную кинематографичную композицию, палитра совпадает (графит/хром/изумруд/золото).
  Мобильный: блок машины/карты по-прежнему скрыт (`hidden sm:block`, как было до этой сессии) —
  регрессии на телефонах нет.
- CSP (`public/_headers`) не требует изменений — `img-src 'self' data:` уже покрывает
  локальные `/images/*.webp`, это не инлайн-скрипты.

## Не закоммичено
Изменения (4 компонента + `Landing/public/images/`) оставлены в рабочем дереве — коммит/пуш/
деплой не запрошены пользователем в этой сессии.
