## Что сделано
- **Курсорное свечение** (`CursorGlow.tsx`) — изумрудный радиальный градиент, следует за
  курсором через rAF, усиливается над `a/button/[data-cursor-glow]`, выключен на touch и
  `prefers-reduced-motion` (оба условия проверяются в JS до монтирования эффекта).
- **Машина реагирует на курсор** (`LuxuryCar.tsx`) — при hover: контраст/яркость фото чуть
  выше, свечение фар (приблизительная позиция поверх фото, точных координат объекта на
  плоском фото нет), дымка позади усиливается, тень/отражение ярче. Всё через CSS-переходы на
  hover-состоянии, без rAF-цикла.
- **CTA "Забрать бонус"** — при hover вокруг кнопки всплывают 4 золотые искры (чистый CSS,
  `.group:hover` управляет `animation-play-state`, JS не нужен), при клике — короткий
  неоновый импульс (`classList` toggle через `e.currentTarget`, не блокирует переход по
  ссылке ни на миллисекунду — реферальная ссылка открывается как обычный `<a target=_blank>`).
- **Карточки статистики в Hero** — вынесены в `HeroStatCard`, добавлен `useCardTilt` (макс 5°,
  уже сам отключается на touch/reduced-motion), бегущий блик по курсору (`useCardTilt`
  расширен — теперь пишет `--shine-x/--shine-y` в % помимо `--tilt-x/--tilt-y` в deg, т.к.
  CSS `calc()` не может мешать deg и % в одном выражении), доп. описание раскрывается по
  hover/focus через `grid-template-rows` transition (не просто opacity — не оставляет пустого
  места в состоянии покоя).
- **Летящие деньги/крипто по всему сайту** — не стал делать вторую DOM-систему частиц.
  Существующий `AnimatedBackground.tsx` (canvas, уже смонтирован в App.tsx на все секции,
  уже perf-hardened) расширен новыми видами частиц (bill/coin/card) с низкой вероятностью
  появления, отрисовываются через `ctx.save/rotate/restore` — на порядок дешевле, чем ещё
  N DOM-узлов на весь документ. Hero сохранил свою отдельную плотную SVG-систему
  (`FloatingWealth.tsx`, сделана в сессии 002) — там её безопасные зоны уже настроены под
  конкретную композицию Hero.
- **Достижения** (`lib/useAchievements.ts`, localStorage, без аккаунта): Первый визит,
  Исследователь (просмотр всех 8 секций через `IntersectionObserver`,
  `lib/useSectionTracker.ts`), Коллекционер (3 пойманных скрытых бонуса), Секрет найден,
  ZHELEZO Mode. Один общий тост (`AchievementToast.tsx`, правый нижний угол, не
  `browser alert`), переключатель "показывать уведомления" — в футере.
- **4 пасхалки**:
  1. 5 быстрых кликов по логотипу → денежный шторм 4с (`MoneyStormOverlay.tsx`) + золотой
     логотип. **Реальный баг**: первые 4 клика открывали реальную ссылку `<a href="/">` и
     сбрасывали счётчик до того, как накопится 5 — теперь каждый клик придерживается ~350мс,
     переход происходит только если 5-й клик не пришёл вовремя.
  2. Слово `ZHELEZO` с клавиатуры → 10 секунд "золотой режим" на весь сайт через один класс
     `.gold-mode-active` на `<html>`, переопределяющий `--color-accent*` — все компоненты,
     уже читающие эти переменные, подхватывают золото бесплатно, без правок по месту.
  3. Редкая молния в окне города (`NightSkyline.tsx`) → модалка с фактами о проекте
     (`ProjectFactsModal.tsx`). **Реальный баг, найденный Playwright**: модалка была вложена
     в контейнер NightSkyline, который получает JS-заданный `transform` от параллакс-хука при
     движении мыши — `transform` на любом предке делает его containing block для
     `position:fixed` потомков (спека CSS), из-за чего фон-подложка модалки схлопывалась до
     820px вместо вьюпорта и пряталась под контентом Hero по z-порядку. Исправлено порталом
     в `document.body`.
  4. Последовательность кликов по фарам машины (лево-право-лево-право) → "Двигатель запущен.
     Добро пожаловать в ZHELEZO." Хитбоксы — приблизительные invisible-кнопки поверх фото
     (точных координат фар в растровом фото нет).
  + Отдельно — редкая кликабельная банкнота с золотой молнией (`SpecialBonusBill.tsx`,
    реальный `<button>`, не canvas — иначе была бы недоступна с клавиатуры) → тост "Секрет
    ZHELEZO найден", инкремент "Коллекционера".
- **Микроанимации**: scroll-spy подсветка активного пункта меню (`lib/useActiveSection.ts`,
  Header.tsx), полоса прогресса прокрутки (`ScrollProgress.tsx`), плавное появление
  выпадающего меню языка, hover-реакция иконок в Games.tsx (в HowItWorks.tsx уже была).
  `scroll-behavior:smooth` и `scroll-margin-top` на секциях — переход по пунктам меню не
  проваливается под фиксированный хедер.
- **Пауза при неактивной вкладке** — класс `.tab-hidden` на `<html>` останавливает все
  CSS-анимации (`animation-play-state:paused`) через `visibilitychange`; canvas-фон уже
  умел это раньше.

## Проверено (Playwright, реальный браузер, не только код)
- Полный прогон по 6 разрешениям (1920/1440/1366/390/375/360) — 0 ошибок консоли, 0
  горизontального скролла.
- Каждая пасхалка вручную через клики/клавиатуру/localStorage-проверку — не просто написана,
  а реально проверена; 3 реальных бага (выше) найдены и исправлены именно на этом шаге, не
  придуманы заранее.
- `prefers-reduced-motion` (реальный контекст Playwright) и клавиатурный фокус на CTA/модалке.
- `npx tsc --noEmit` и `npm run build` чисто после каждого крупного блока правок.
- Lighthouse: прогнан и на `vite dev` (бессмысленно — LCP 50с, троттлинг Lighthouse душит
  несобранные ES-модули), и на честном `vite build && vite preview` (Performance 66,
  Accessibility 100, SEO 100, Best Practices 77). TBT ~1.4с — большая часть замера уходит в
  "Unattributable" (лог `bootup-time`/`long-tasks`), что уже задокументировано в памяти
  проекта (сессия аудита 2026-07-21) как артефакт этой песочницы, а не код проекта. Сделал
  один обоснованный perf-фикс (отложенный монтаж декоративных виджетов через
  `requestIdleCallback`, `lib/useDeferredMount.ts`) — цифры не сдвинулись, что подтверждает:
  узкое место не в новом коде. **Рекомендация пользователю**: перепроверить реальный
  PageSpeed Insights на задеплоенной версии, локальным цифрам в этой песочнице доверять
  нельзя (как и в прошлых аудитах).
