# Сессия 2026-07-27 (004) — GPT-консультация по продвижению + Hall of Fame

## Контекст
Пользователь попросил "посоветоваться с GPT" по продвижению сайта после редизайна/пасхалок
(сессия 003). Проверил сначала, что уже сделано по growth (`ROADMAP.md`, `REPORT/GROWTH_PLAN.md`,
`Texts/`) — не стал предлагать то же самое заново. Спросил `ask_gpt` (MCP) как второе мнение,
дав ему полный контекст: уже одобренные/отклонённые каналы, юридическое ограничение (без
фабрикованного соцдоказательства, без обещания денег за пасхалки).

## Идея от GPT (отфильтрована, не всё принято как есть)
Фрейм "мини-ARG": продвигать не "казино", а "охоту за секретами" с наградой в виде статуса
(роль/Hall of Fame), не деньгами. Пользователь выбрал 2 направления из предложенных:
1. Код: кнопка "Поделиться", `?gold=1`, страница Hall of Fame.
2. Контент для заявок в дизайн-витрины (Awwwards и т.п.).

**Не стал делать** (осторожность, не входило в выбор пользователя): Zealy/Galxe-квесты (обычно
подразумевают токен-вознаграждение — конфликт с "без денежных призов"), Discord-роли (бот всё
ещё не задеплоен, см. предыдущие сессии), Telegram-серия постов (пользователь публикует сам).

## Сделано

### 1. Кнопка «Поделиться» в тосте достижений
`AchievementToast.tsx` — кнопка рядом с текстом тоста открывает Twitter/X intent-ссылку с
готовым текстом (`achievements.shareText`, переведено RU/EN/VI) и UTM-меткой
(`utm_source=share&utm_medium=achievement_toast`). Новое событие аналитики
`easter_egg: { id: 'share_click' }`.

### 2. `?gold=1` — прямая ссылка в золотой режим
Логика активации "золотого режима" вынесена из `useSecretWord.ts` в отдельную экспортируемую
`activateGoldMode(source, title, desc)` — теперь её вызывают И клавиатурная пасхалка
(`source: 'secret-word'`), И новый `useEffect` в `App.tsx`, читающий `?gold=1` из URL
(`source: 'query-param'`). Нужно для скриншотов/трейлеров в контенте без необходимости
печатать секретное слово в кадре.

### 3. Новая страница Hall of Fame
Полноценная отдельная страница (`/hall-of-fame/`, `/en/`, `/vi/`) — тот же паттерн, что уже
использован для `/community/` (собственные статические HTML-точки входа, `HallOfFamePage.tsx`,
3 bootstrap-файла, запись в `vite.config.ts`). Контент: список из 5 пасхалок с намёками (не
полными спойлерами), честный пустой список ("пока никто не прислал"), инструкция как попасть
в список (скриншот + любой канал связи → добавим вручную), явная оговорка об отсутствии
денежных призов. **Список сознательно пуст — никаких выдуманных записей** (GEMINI.md §8).

Технические детали:
- Новый CSP sha256-хэш для `hall-of-fame/index.html`'s auto-detect-языка скрипта
  (отличается от community/root — редиректит на `/hall-of-fame/en//vi/`), добавлен в
  `public/_headers`. En/Vi-версии переиспользуют уже зарегистрированный хэш theme-скрипта
  (байт-в-байт идентичен остальным страницам) — новых хэшей для них не потребовалось.
  Официальный `scripts/verify-csp-hashes.mjs` проходит чисто.
- 6 новых URL в `sitemap.xml` (3 языка × сам URL + hreflang alternates на все 3), `changefreq:
  weekly` (список ожидаемо обновляется).
- Ссылка в `Footer.tsx` (колонка "Поддержка", видна на каждой странице сайта).

### 4. Контент для дизайн-витрин
`Texts/design_showcase_submissions.md` — заголовок/тэглайн/описание (EN, 2 длины)/теги/
credits-шаблон для Awwwards, One Page Love, CSS Design Awards, SiteInspire + отдельный план
кадров для Dribbble/Behance кейса. Честно отмечено: сама подача заявок — вручную (нет
браузера для интерактивных веб-форм), модерация ручная и не гарантирует принятие.
